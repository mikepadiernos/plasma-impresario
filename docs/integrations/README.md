# Integrations

**[Documentation](../README.md)** · **[Roadmap](../ROADMAP.md)** ·
**[Scope](../philosophy/scope.md)** · **[Caveats](../CAVEATS.md)**

Integration guides list the intended behavior, suggested approaches,
recommendations and verification scenarios for each integration. They keep
planned work separate from the current mail baseline, which is recorded in the
[UI](../parity/ui.md) and [backend](../parity/backend.md) parity guides.

| Guide                            | Purpose                                                | Roadmap                                                                                                                                                                                         |
| -------------------------------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 🖥️ [KDE Plasma](kde-plasma.md)   | Desktop services, KDE conventions and system behavior  | M05.01–M05.03 in [M05](../ROADMAP.md#m05-desktop-integration-and-provider-support)                                                                                                              |
| 🧩 [Plasma Opus](plasma-opus.md) | Cross-app, workspace, theme and productivity workflows | M05.03, [M07](../ROADMAP.md#m07-settings-and-workspace-configuration), [M08](../ROADMAP.md#m08-themes-and-branding-foundation), [M11](../ROADMAP.md#m11-nextcloud-and-digital-asset-management) |

Most integrations are planned. Each guide starts with a table that separates
what the client does today from planned work.

> [!IMPORTANT]
>
> An integration is complete only when authentication, error recovery, privacy
> behavior and offline or unavailable-service handling are all defined.
